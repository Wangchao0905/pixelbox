## 0. 一句话

**P0 解决的是「有没有」**（动效有没有、页面有没有层次、导航有没有逻辑）。
**P1 解决的是「齐不齐」** —— 同一个东西在不同页面是不是同一个样子。

不齐的地方有三处，都有数字：

| 不齐的东西 | 数字 |
|---|---|
| 生成页的结构 | **5 个**是三层卡（页头 + input-card + settings-card），**2 个**是平铺块 |
| 加载态 | `spinner` 只用在 1 个组件；`skeleton-pulse` **定义了但 0 个页面用** |
| 颜色 | 颜色令牌 **11 个**，硬编码色 **131 处 / 100 个不同值** |

`forme.scss` 里有**两个** `page { ... }` 令牌块（**第 62 行**与**第 2093 行**）。
⚠️ 行号会漂：09-27 的 P1-1 加了 19 行 CSS，块 2 就从 **L2074** 挪到了 **L2093**
（本文 §4.1 那批证据是在 L2074 时跑的）。**用之前自己 `grep -n "^\s*page\s*{" src/styles/forme.scss` 重新确认。**
两者选择器与特异性完全相同 ⇒ **后面的整块覆盖前面的**。

| `--bg` | `#101212` | `#050505` |
| `--surface` | `#171b1b` | `#0e0e0e` |
| `--surface-2` | `#1a1e1e` | `#141414` |
| `--surface-3` | `#181d1c` | `#191919` |

> ⚠️ **本方案第一版把这里写成「7 个」并漏了 `--lime`** —— 因为 `--lime` 在块 2 里是
> **同一个值**，肉眼核对时会被当成「没被覆盖」。**数这种「谁覆盖谁」的表必须用脚本，
> 不能靠眼看。** 这也是本方案唯一一处自己写错、后被程序纠正的地方。

块 1 里另外 16 个**非颜色**令牌（`--safe-b` / `--dock-h` / `--page-pad` …）是**活的、必须留**。
⇒ 所以**不能**把块 1 整块删掉，也**不能**写「`page{}` 只能有一个」这种门禁（会永远为红）。

⚠️ **而且那 7 个旧色值还在别处硬编码着，一共 14 处**：
`#f4f4ef` ×3、`#101212` ×4、`#171b1b` ×2、`#181d1c` ×2、`#1a1e1e` ×1、`#969897` ×1、`#282c2c` ×1。

⇒ 这些规则是**照着旧调色板写的**，旧调色板被覆盖之后它们不会跟着变 ——
它们现在渲染的是「上一个设计版本的深色」，和新配色只差一点点。
**这正是「配色我基本满意、但总感觉哪里不齐」的来源。**

### 2.6 🔴 这一项踩出来的四条新铁律（已进 `MEMORY.md`）

1. **判据要锚「条目形态」，绝不锚裸子串。** `composer-block-note` / `composer-blocker`
   都包含 `composer-block` ⇒ `includes('composer-block')` **假红**。改用 `hasClassLiteral()`
   （前后必须是空白/引号/反引号）。**控制组 C0b 直接跑两种判据证明**：`{"naive":true,"anchored":false}`。
2. **拿「从表里算出来的结果」去比那张表 = 恒真的假门禁。** 例外表自检第一版写成
   `SHELL_CLASSES.filter(不在例外表里) === 例外表` —— 两边同源 ⇒ 永远相等。
   对抗 **M6**（往例外表多塞一个类）**全绿**才暴露。改成去查**源文件**才真的会红。
3. **`cssBlock` 只取第一条匹配规则。** 同一选择器有多条时（`.input-card .composer-section-title`
   有 2 条）会静默读到 `null`。新增 `cssAll()`（全部匹配、`;` 连接）。
   ⚠️ 产物侧 `declsFor` **早就为这个坑写过注释**，源码侧又踩一次。
4. **改一处共享资产，别处门禁可能变假红 —— 而且要用更强的判据修，不能用更松的。**
   `cover-inspiration-recreate.jpg` 被**两个**页面 import ⇒ Webpack 把它提升进
   `dist/common.js`，首页 chunk 里只剩 `m=a(2888)`，路径字符串消失 ⇒
   旧门禁「首页真的引用了轮播封面」变红。修法是新增 `assetModuleId()` 找到模块号，
   再要求首页含 `a(<id>)`；**没有**退化成「全库扫一遍」（那只要别的页面 import 过就永远绿）。

## 3. P1-2 · 加载态补齐 —— ✅ 2026-09-27 已完成（**范围比原方案小**）

**问题**：`skeleton-pulse` 定义了但没人用；除资产页外，其它列表页没有加载态。

### 🔴 原方案的前提是错的（与 P0-2 同类）

方案写的是「**三个**列表页补骨架屏：资产库、产品模板库、头像模板库」。
取证后发现**只有资产库真的异步取数据**：

| 页面 | 数据来源 | 有异步吗 |
|---|---|---|
| 资产库 | `loadAssets()` → `GET /api/assets` | ✅ 真的异步 |
| 产品工作室 | `productReplacementTemplates` / `PRODUCT_STUDIO_INTENTS`（**本地常量**） | ❌ 同步渲染（0 处 await / useDidShow） |
| 头像模板库 | `avatarTemplates`（**本地常量**） | ❌ 同步渲染 |

⇒ 给后两页加数据骨架屏，**它永远不会显示** —— 那就是**留一条永远为真的断言**。
这两页上唯一异步的是**封面图**（远程图 + `lazyLoad`）。

**王定的处理**：**只做资产库**。（「封面图骨架」是一个可选的新增视觉元素，暂不做。）

### 做了什么

1. **资产库**：把 `.asset-loading`（一行「正在同步资产库…」文字）换成真骨架屏。
   - 形状：**2 组 × 4 格**，与真实列表的 2 列网格对齐。
   - 🔴 占位块**复用真实列表的类**（`.asset-group` / `.asset-grid` / `.asset-cell` /
     `.asset-img`）⇒ 几何**不可能漂**。实测 `.asset-img` = **174 × 193.33** ⇒ 比值 **0.9000**，
     与真实缩略图的 `aspect-ratio: 0.9` 完全一致。
   - 动画用现成的 `.skeleton-pulse`（`@keyframes pulse`，**不改动效参数**，见 §9）。
   - 只在**首次**进入显示；之后切回来仍是静默刷新（`loadedOnce` 逻辑没动）。
2. 删掉 `.asset-loading` 的样式（连同它在逗号组里的成员 —— 摘成员、**保留块体**，铁律 #12）。
3. **生成中的等待态**（`GenerateDock` 的 spinner）**没动**，仍在原状。

### 4.2 「零观感变化」的像素证明（以及一个**无效仪器**的发现）

做法：不动源码，直接改**编译产物** `dist/app.wxss`，让模拟器重载后截图比对。

| 用例 | y≥60 内幅度≥8 的像素 | 最大幅度 | 结论 |
|---|---|---|---|
| ① **探针**：`--bg` 改成红色 | **84,628** | 250 | 重载生效、仪器能检出真改动 |
| ② **死声明塞回**第一个 `page{}` 块 | **0** | 1 | 与「什么都没改」的控制组**读数完全一致** |
| ③ **控制组**：还原后 vs 基线（CSS 逐字节相同） | **0** | 0 | 仪器噪声地板 = 0 |

🔴 **但这里踩了一个大坑，值得记下来**：一开始我用「**像素个数**」当判据，
结果**什么都不改**、只刷新重截，两次也差 **7.5k 像素**，直接误判成「它们不是死代码」。
原因：① 首页状态栏有一条**活的时钟**（y≈18–30，幅度可达 **250**）；
② 其余像素有 **±1** 的四舍五入抖动，**像素数能到 1.6k**。
⇒ 在这个页面上**像素个数不是有效指标**（时钟一动就上千）；
有效指标是**幅度**，并且**只比 y≥60 的应用内容**。
并且**必须先跑探针变异**证明仪器没瞎 —— 否则「没变化」可能只是「没生效」。
