## 二、87 这个数字的验证链（5 条独立证据）

不想凭一个脚本下结论，所以从 5 个方向交叉验：

1. **源码扫描**（词边界）：`src/**/*.tsx?` 里 0 命中。
2. **编译产物扫描**：这 87 个类名**一个都不在** `dist/common.js` 里（词边界匹配）。
   组件没引用 ⇒ 编译不出来 ⇒ 这是与源码扫描**完全独立**的第二条路径。
3. **子串扫描**（故意放宽到子串）只命中 2 个，且都能解释：
   - `mono` → 命中在 `ink-monograph`（模板 id）里，`.mono` 本身 0 命中；
   - `option-pill` → 命中在 `option-pills`（复数容器）里，`.option-pill` 本身 0 命中。
     这正是本项目记过的**子串陷阱**，`contrast-tokens.py` 的注释里也写了。
4. **动态拼接排查**：全仓库所有 `className={`...`}` 都是「**字面**基类 + **字面**修饰类」
   （`base ${cond ? 'mod' : ''}`），没有任何变量被插进类名。
   唯一用到 `poster-` 片段的地方（`` templateId: `poster-${direction.id}` ``、
   `services/create-ui.ts` 的 `poster: 'poster-'`）拼的是 **templateId，不是 className**。
5. **独立 grep 抽查** 10/10 全部 0 命中。

⇒ **87 个死类名，0 个误判。**

## 四、顺手发现并修复的**诊断脚本缺陷**

`_diag/contrast-feature-cards.py` 里，行内 ✅/⚠️ 标记**只看标题**，而同一行末尾还打印 kicker、
汇总行却用 `min(标题, kicker)` —— 三者不同源。后果是出现过：

```
视口430: 标题最低 4.98:1 ... | kicker 最低 4.18:1  ✅     ← ✅ 旁边跟着低于 4.5 的数字
```

修复：行内标记改为按**本行最低值**判定，并指名「← 标题不达标 / ← kicker不达标」。
**修复后不合格的行从 2 行变成 4 行**（原先是假绿）。

并加了一条自检：逐行最低值与汇总 `worst` 必须一致，否则 `sys.exit`。
自检已做**对抗测试**（故意注入分叉 → 退出码 1，报
`✗ 自检失败：逐行最低 3.6855 与汇总 worst 1.0000 不一致`），临时文件已清理。

> 这与本项目的铁律一致：**沉默的失败最危险**。一个「看起来正常」的 ✅ 会让人跳过那个数字。
